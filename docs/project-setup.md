# Project Setup

## Prerequisites

- [Go](https://go.dev/dl/) 1.25 or later

## Building

```bash
# Clone the repo
git clone <repo-url>
cd harbor

# Download the Tailwind CLI binary (one-time)
harbor tailwind download

# Build the binary (rebuilds CSS + templ + compiles Go)
harbor build

# Go-only build (skip CSS/templ rebuild)
harbor build --no-css

# Or build + install to GOPATH/bin
make install
```

## Development

### CSS

The project uses Tailwind v4 via the standalone CLI — no `npm`, no
`package.json`, no `node_modules`. CSS is generated by scanning Go source files
for class usage:

```bash
# Generate CSS from web/input.css + scan Go files for Tailwind classes
make css

# Fetch the Tailwind CLI binary (run once per checkout)
make tailwind-download   # same as: harbor tailwind download
```

The generated CSS is copied into `internal/web/app.css` (committed, for
`//go:embed`) and served at `/css/app.css`.

### templ

`*.templ` components live in `internal/render/` and are compiled to committed
`*_templ.go`. Regenerate with `templ generate` (run automatically by
`harbor build` when the templ CLI is present):

```bash
go install github.com/a-h/templ/cmd/templ@v0.3.1020
templ generate
```

### Architecture

The codebase is structured in layers:

```

├── cli/            # Cobra commands — injected store, testable seams
│   ├── root.go           # mustStore() context injection; --json persistent flag
│   ├── helpers.go        # formatTable / resolveWorkspace / readBodyFile helpers
│   ├── page.go           # page CRUD (managed store import, status, tags)
│   ├── workspace_*.go    # workspace create/list/stats/use/rename/delete
│   ├── tag.go            # tag CRUD (name + semantic description)
│   ├── search.go         # FTS search + --rebuild-index
│   ├── comments.go       # comment lifecycle + watch
│   ├── change.go         # data-cf-change walkthrough records
│   ├── asset.go / asset_registry.go # assets/ management
│   ├── nav.go            # navigate the dashboard via /api/notify
│   ├── notify.go / exec.go  # server notifications / commands from the CLI
│   ├── start.go / dev.go / stop.go / daemon_*.go  # server lifecycle daemon
│   ├── config.go / init.go / migrate.go
│   ├── build.go / tailwind*.go / upgrade.go / version.go
│   ├── skills*.go        # skills check/install/uninstall
│   └── *_test.go         # CLI tested against in-memory SQLite
├── config/         # harbor.toml (data_dir, port) — paths, load, save
├── db/             # Data access layer — SQLite via sqlx, typed query methods
│   ├── db.go            # Store + connection lifecycle
│   ├── models.go        # Domain structs (Workspace, Page, Tag, Comment, Change)
│   ├── pages.go / workspaces.go / tags.go / comments.go / settings.go
│   ├── workspace_store.go # Scoped store bound to one workspace (assets)
│   ├── assets.go        # assets/ management + path guard
│   ├── layout.go        # on-disk workspace layout + SafeJoin guard
│   ├── fileutil.go      # file copy/atomic-write helpers for the managed store
│   ├── fts_query.go     # Centralised FTS5 query builder
│   ├── seed.go / seed/  # Embedded seed assets (copy-code.js, fonts)
│   ├── scan.go          # Generic row scanner (deduplicated loop)
│   ├── slugify.go       # slug generation
│   └── *_test.go        # Integration tests with temp SQLite DBs
├── extract/        # HTML→plaintext text extraction (goquery-based) + formats
│   └── chapter.go detect.go docx.go epub.go fromfile.go pdf.go rtf.go ...
├── markdown/       # Markdown→HTML rendering (goldmark)
├── migrate/        # Embedded SQL migrations (goose v3)
├── render/         # HTML output — two families:
│   ├── library.go / pageview.go   # self-contained strings (inline CSS+JS), the primary surface
│   ├── frame.templ / views.templ / iframe_not_found.templ  # workspace/doc pages (Tailwind CSS)
│   └── icons.go, models.go, pageview_scripts.go
│       # pageview_scripts.go embeds the JS assets: harbor-livesync.js,
│       # pageview-shell.js, pageview-tour.js, pageview-annotations.js, quiz-attempt.js
├── server/         # HTTP server — thin handlers, no HTML strings
│   ├── mux.go       # Route handlers + JSON API (NewMux — testable seam)
│   ├── server.go    # Server lifecycle (start/stop/PID)
│   └── events.go    # Server-sent events / /api/notify
├── skills/         # Bundled skills manifest + embedded agent skill
│   ├── manifest.go  # Skill definitions (name → install targets)
│   └── harbor/      # The skill payload (SKILL.md + CLI reference)
├── urls/           # URL scheme — one owner for workspace/page paths
├── version/        # Version detection (ldflags or debug.BuildInfo + VCS)
└── web/            # Embedded CSS, favicons, manifest, service worker (generated/committed)
```

### Key Design Decisions

- **Singleton CLI binary** — everything in one binary (including CSS, skills,
  and seed assets), no runtime dependencies
- **Tailwind via standalone CLI** — no Node.js in the build chain
- **Testable seams** at every layer: CLI (`mustStore`), rendering, data access
  (`WorkspaceStore`), HTTP (`NewMux`)
- **Workspace scoping enforced by types** — `WorkspaceStore` wraps a private
  store; callers cannot bypass the workspace boundary or call raw SQL
- **Read-only web UI** — all mutations happen through the CLI; the dashboard
  just reads the DB and serves page files
- **Managed page store** — imported pages are real files under
  `<data_dir>/store/<workspace>/`, owned by harbor; the DB holds metadata + the
  FTS index
- **No inline shell escaping** — multiline content is always passed via
  `--body-file` from a real file
- **Embedded assets** — CSS, favicons, fonts, and seed assets are
  `//go:embed`'d into the binary; no external file dependencies at runtime

```bash
make test   # go test ./... (real SQLite temp files, no mocks)
```

## Releases

Tag a version to trigger the GitHub release workflow:

```bash
git tag v0.1.0 && git push --tags
```

GoReleaser (`.goreleaser.yaml`) cross-compiles linux/darwin/windows ×
amd64/arm64 and produces archives, a checksums file (cosign-signed keyless),
and Linux packages.
